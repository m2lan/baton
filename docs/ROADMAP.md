# Baton 路线图

> 起点：v0.1.4（2026-10）｜ MIT ｜ https://github.com/m2lan/baton

核心判断：**先把「能用」变成「敢用」，再把「群聊」做成真正省时间的工作流，最后才谈规模化。**
在核心体验没跑顺之前堆功能，只会让一个没验证好的东西越来越重。

---

## 阶段一：把「能用」变成「敢用」

**版本** 0.1.x → 0.2.0 ｜ **目标** 核心路径不出错，陌生人装完能自己跑起来

| # | 任务 | 现状 | 做什么 | 涉及文件 | 验收标准 |
| --- | --- | --- | --- | --- | --- |
| P0-1 | **超时与空转兜底** | ❌ 完全没有超时，CLI 卡住会一直挂着 | ① 单轮超时（默认 5 分钟，超时 kill 并提示「本轮到 xx 卡住了」）<br>② 群聊无进展检测：连续两轮输出相似度 > 0.9 判为原地打转，停下并提示<br>③ 有了 ①② 后 `MAX_TURNS` 从 24 提到 60（轮数退居次要防线） | `electron/runner.js`<br>`electron/room.js` | 故意让 CLI 挂起，5 分钟内自动停止并给出可读原因；两个 Bot 互甩锅时 3 轮内被识别 |
| P0-2 | **首次使用引导** | ⚠️ 有 hero 空态，但一个 CLI 都没装时只是一排灰卡片 | ① 零 CLI 时换成三步引导（装 CLI → 登录 → 建 Bot），而不是罗列 11 个灰卡片<br>② 每个未安装的 CLI 卡片直接给安装命令 + 复制按钮<br>③ 未登录时在会话里给一键 `/login`（已部分具备，需补全引导文案） | `renderer/index.html`<br>`renderer/app.js` | 模拟全新用户（清空 PATH），不看文档也能装好并跑通第一个 Bot |
| P0-3 | **群聊交班实机验收** | ⚠️ 逻辑上周刚改，未跑过真实任务 | 用写作小组真跑 3 个任务，记录每个卡点。验收清单见下方 | — | 3 个任务全程无需手动接管即可收尾 |
| P1-4 | **Mac / Linux 实机验证** | ❌ 代码就绪但只在 Windows 实测过 | 从 CI artifact 下载到 Mac 实跑，重点验证三处：内嵌终端（node-pty）、系统终端调用、PATH 探测 | `electron/platform.js`<br>`electron/pty.js` | Mac 上能正常建 Bot、跑任务、开终端 |

### P0-3 验收清单

| 场景 | 预期 |
| --- | --- |
| 单 Bot 往返 | 出方案 → 评审 → 回改 → 再审，自动收尾 |
| 三 Bot 接力 | mimo → hy4 → writer 依次交接，上下文不丢 |
| 中途 stop | 立即停止当前 Bot，队列清空，界面状态归位 |
| CLI 报错（未登录 / 命令不存在） | 会话里出现可读提示，不是空白或卡死 |
| 进度条 | 每轮切换时「谁在跑 / 排队」实时更新 |

## 阶段二：把「群聊」从 demo 变成工作流

**版本** 0.2 → 0.3 ｜ **目标** 让多 Bot 协作真正比「我自己挨个问」省时间

| # | 任务 | 现状 | 做什么 | 涉及文件 | 验收标准 |
| --- | --- | --- | --- | --- | --- |
| P1-1 | **任务模板** | ❌ 每次都要手动组群、手写角色设定 | 预置三类房间，一步建好：<br>· 写作小组（作者 / 审稿 / 读者视角）<br>· 代码评审（实现 / 审查 / 测试）<br>· 需求 → 方案 → 实现（产品 / 架构 / 编码）<br>每个模板自带角色 systemPrompt 和交接规则 | 新增 `electron/templates.js`<br>`renderer/index.html` | 新建群聊时选模板，成员和角色设定自动填好 |
| P1-2 | **中途可介入** | ❌ 只能 stop 全部再重来 | 当前轮跑完后插入用户消息，不打断正在跑的 Bot；队列保留 | `electron/room.js` | 跑到第 3 轮时说一句，第 4 轮能读到并响应 |
| P2-3 | **并发执行** | ❌ 完全串行，一轮只有一个 Bot 在跑 | 同一轮里互不依赖的成员并行。**前提：各自独立工作目录**，否则同目录写文件会冲突 | `electron/room.js` | 两个 Bot 同时改不同文件时耗时接近单 Bot |
| P2-4 | **共享决策板** | ⚠️ 上下文已改三层，但结论靠启发式抽取 | 房间内维护一块共享「决策板」，Bot 有结论时主动写入，后续所有成员都读。比猜「哪段是结论」更准 | `electron/room.js`<br>`electron/store.js` | 长对话（30+ 轮）后仍能准确复述早期决策 |

## 阶段三：让陌生人能用

**版本** 0.3+ ｜ **目标** 跨语言、可带走、装得上

| # | 任务 | 现状 | 做什么 | 涉及文件 | 验收标准 |
| --- | --- | --- | --- | --- | --- |
| P1-1 | **界面 i18n** | ❌ 界面全中文，README 才是双语 | 抽出 `strings.js`，按系统语言自动切换，设置里可手动改 | 新增 `renderer/i18n.js`<br>全部 `renderer/*` | 英文系统默认英文界面，中文系统默认中文 |
| P2-2 | **会话导出** | ❌ 聊天记录只能在应用里看 | 导出为 Markdown：每个 Bot 的发言 + 工具调用摘要，可直接贴进文档 | `electron/main.js`<br>`renderer/app.js` | 导出的 md 内容完整、格式可直接使用 |
| P3-3 | **分发渠道**（可选） | ⚠️ 只有 GitHub Release | 上架 Windows 的 winget / scoop、macOS 的 Homebrew tap，让用户 `winget install baton` 就能装 | 新增 `packaging/` | 一条命令完成安装 |

> 代码签名不在计划内。未签名包能正常安装和自动更新，只是首次运行多一步「仍要运行」提示，README 里已写明绕过方式。

## 明确不做

| 不做 | 原因 |
| --- | --- |
| 云同步 / 账号体系 | 会毁掉「数据不出本机」这个最硬的卖点，还要背上服务器成本 |
| 移动端 | 本地 CLI 编排在手机上没有使用场景 |
| 自己做模型接入 | 那是 Qoder / Trae 的事，Baton 的定位是**复用**本机已装的 CLI |

---

## 建议的推进顺序

```
P0-1 超时兜底 ──┐
P0-2 首次引导 ──┼──→ 0.2.0 发版 ──→ 阶段二
P0-3 交班验收 ──┤
P1-4 Mac 验证 ──┘
```

前四项都是「让现有功能不出错」，做完再谈新能力。其中 **P0-1 优先级最高**——现在 CLI 卡住没有任何兜底，这是随时会踩到的坑。
