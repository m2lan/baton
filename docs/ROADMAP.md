# Baton 路线图

> 当前版本：v0.6.0（2026-11）｜ MIT ｜ https://github.com/m2lan/baton
>
> 核心判断：**先把「能用」变成「敢用」，再把「群聊」做成真正省时间的工作流，最后才谈规模化。**
> 在核心体验没跑顺之前堆功能，只会让一个没验证好的东西越来越重。

## 群聊回归清单

改动 `room.js` 后过一遍，防止把已验证的行为改坏：

| 场景 | 预期 |
| --- | --- |
| 单 Bot 往返 | 出方案 → 评审 → 回改 → 再审，自动收尾 |
| 三 Bot 接力 | A → B → C 依次交接，上下文不丢 |
| 中途 stop | 立即停止当前 Bot，队列清空，界面状态归位 |
| 中断后重启 | 会话顶部出现中断提示；继续只排未开始的成员 |
| 正常结束 | `data/runs/live/` 不留快照，Runs 里状态为完成 |
| CLI 报错（未登录 / 命令不存在） | 会话里出现可读提示，不是空白或卡死 |
| 进度条 | 每轮切换时「谁在跑 / 排队」实时更新 |

运行：

```bash
npm test          # attach / room / p2 / recover / shutdown
npm run ui:check  # 渲染层冒烟（需应用带 --remote-debugging-port=9222 启动）
```

## 明确不做

| 不做 | 原因 |
| --- | --- |
| 云同步 / 账号体系 | 会毁掉「数据不出本机」这个最硬的卖点，还要背上服务器成本 |
| 移动端 | 本地 CLI 编排在手机上没有使用场景 |
| 自己做模型接入 | 那是 Qoder / Trae 的事，Baton 的定位是**复用**本机已装的 CLI |
| 进程级断点续跑 | CLI 子进程状态不可序列化；假装能续跑比重新开始更危险 |
| 团队级 Policy / Mandate / 准入表 | 个人工具没有「陌生人提需求」场景，规则表会变成没人维护的配置债 |
